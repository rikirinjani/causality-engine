What makes it different

Three properties most simulations give up.

Plenty of games simulate an economy. What CE keeps that they usually discard is the ability to reproduce a run exactly, explain any value in it, and split it into alternatives.

Determinism

Same seed, same actions, same world — down to the bit. State identity is a SHA-256 hash of the world, so two runs are either identical or provably not.

Verified across seven environments — Linux, macOS and Windows on Node 20 and 22 — all producing 5404d32e…

Retrospective attribution

CE records a provenance graph as it propagates. Ask why a value is what it is and it walks the graph back to the originating action. If it can't explain something, it says so rather than guessing.

In the demo above: why(RF:price:grain) → rooted in destroy_infrastructure at tick 0

Branching and rewind

Checkpoint a world, rewind it, or fork an independent timeline and take a different action. Both timelines stay causally distinct — CE never collapses two histories that happen to look alike.

Physical state and causal history hash separately, so same world / different history is representable

The boundary

CE owns causality. Your game owns everything you can see.

This split is the whole design. Get it wrong and determinism, attribution and branching all stop meaning anything — because your game and CE would disagree about what is true.

Your game Rendering · animation · camera · UI · player input · audio · presentation
Adapter Player intent → CE intervention · CE state → game projection · transport · reconnection
Causality Engine World state · causal rules · propagation · deterministic RNG · events · provenance · persistence · branching · rewind · timeline identity

Your game decides what the player did. CE decides what it caused. No causal rule and no RNG belong on your side of that line — and the shipped Godot addon is audited to contain neither.

Install

Two ways in.

Not on npm yet. npm install causality-engine will 404. Both pieces download from the GitHub release — no repository clone needed.

TypeScript · in-process

No second process, no network hop, no runtime dependencies.

curl -LO https://github.com/rikirinjani/causality-engine\
/releases/download/v1.0.0-rc.1\
/causality-engine-1.0.0-rc.1.tgz

npm install ./causality-engine-1.0.0-rc.1.tgz
import { createGame, intervene, step, inspect }
  from "causality-engine/product";

const game = createGame({ seed: 42 });

intervene(game, {
  action: "destroy_infrastructure",
  target: { type: "infrastructure", id: "grain_road" },
  location: "RF",
});

step(game, 5);
inspect(game).regions.RF.prices.grain;  // 13.13

Requires Node 20+ and an ESM project ("type": "module").

Godot 4 · addon

Tested on Godot 4.3, 4.4 and 4.7.2.

cd your-godot-project
curl -LO https://github.com/rikirinjani/causality-engine\
/releases/download/v1.0.0-rc.1\
/causality-engine-godot-addon-1.0.0-rc.1.zip
unzip causality-engine-godot-addon-1.0.0-rc.1.zip
var ce := preload(
  "res://addons/causality_engine/ce_client.gd"
).new()
add_child(ce)

ce.connected.connect(func(id, _tl):
    ce.create_world(42)
    ce.request_snapshot()
)
ce.connect_to_ce()

Godot talks to a CE runtime over WebSocket, so this path also needs npm run serve from a clone. See Godot integration.

Limitations

What CE is not.

Listed plainly, because finding these out after you've integrated is worse than reading them now.

The WebSocket runtime has no authentication

It binds 127.0.0.1. Anything that can reach the port can create worlds, read state and fork timelines. Exposing it beyond localhost needs a security layer CE does not provide.

Nobody outside the project has used it

Every test above was written and run by the author. That is the reason this is a release candidate.

Not a game engine

No rendering, animation, input or audio. CE is a layer underneath whatever engine you already use.

Single process

No multiplayer, no distributed simulation, one world per runtime process.

At-least-once event delivery

Not exactly-once. Facts can be redelivered; consumers must tolerate it. The attempt count is visible so you can tell.

History is bounded

Old events and provenance are evicted to bound memory. Eviction is always reported — never silent — and an incomplete explanation says so.

Determinism is tested, not proven

Reproduced across seven environments. There is no formal proof, and floating-point behaviour on untested platforms is not guaranteed.

One demonstrated scenario

A single town with four domains. Scaling to large worlds has not been established.

The ask

I need someone to tell me where my documentation fails.

I've verified this engine about a thousand ways. I have no idea whether anyone else can install it.

No developer outside this project has ever used CE. That single gap — not a missing feature, not a failing test — is what stands between the release candidate and a 1.0. You cannot honestly call something adoptable until somebody else has adopted it.

What it involves

  1. 30–45 minutes, in one sitting.
  2. Pick a track: TypeScript or Godot.
  3. Install CE into an empty project.
  4. Create a world, take one action, watch a consequence.
  5. Save and reload it.
  6. Tell me every place you got stuck.

What I'm actually after

  1. The step where the docs assumed knowledge you didn't have.
  2. The command you expected to work that didn't.
  3. The API you went looking for and couldn't find.
  4. The moment you wanted to read the source — that one is gold.
  5. Abandoning halfway with a clear reason is more useful to me than succeeding by guesswork.
